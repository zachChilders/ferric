# M9 — Task 5: VM — New Opcodes + Handler Stack

> Implements the four new bytecode opcodes (`Perform`, `PushHandler`,
> `PopHandler`, `Resume`), the handler stack, and continuation capture/restore.
> Replaces the M8 cooperative scheduler with a handler-based equivalent.
>
> **Prerequisites:** [Task 1](m9-01-common-types.md) (the `Op::*` enum variants
> live in `ferric_common`) and [Task 4](m9-04-lowering.md) (the lowering pass
> emits these opcodes) must be complete.
>
> See [m9-00-overview.md](m9-00-overview.md) for milestone-level design
> decisions.

---

## What this task does

Adds the runtime support for algebraic effects: a separate handler stack
maintained alongside the existing call stack, four new opcodes that manipulate
it, and a continuation slab that stores captured execution state for one-shot
resume. Replaces the bespoke M8 async scheduler with a built-in `Async`
handler that uses these primitives.

The `Executor` trait signature is unchanged. All M1–M8 sync programs continue
to run on the same VM with no behaviour difference; the handler stack is empty
during their execution.

---

## Handler stack

Add a `handler_stack: Vec<HandlerFrame>` to `BytecodeVM`:

```rust
struct HandlerFrame {
    effect_tag:  u16,                       // which effect this handles
    op_handlers: HashMap<u8, HandlerFn>,    // op_tag → handler function pointer / closure
    return_addr: usize,                     // where to continue after PopHandler
}
```

The handler stack is separate from the call stack. It is checked on every
`Op::Perform`.

---

## Continuation slab

A continuation captures `(ip, call_stack_depth, locals)` — enough state to
resume execution exactly once. Continuations are stored in a slab allocator on
the VM and identified by `ContinuationId`. Each `ContinuationId` carries a
"consumed" flag; resuming a consumed continuation is `EffectError::ResumedTwice`.

One-shot only: there is no need to clone or refcount continuation state.

---

## `Op::PushHandler`

Pops a handler descriptor from the stack (compiled from a `handle...with`
expression), pushes a `HandlerFrame` onto the handler stack. Execution continues
with the body of the `handle` expression.

## `Op::PopHandler`

Pops the top `HandlerFrame`. Called after the body of a `handle` expression
completes normally (without performing any handled effect).

## `Op::Perform`

Walks the handler stack top-to-bottom looking for a frame that handles this
effect and op. When found:

1. Captures the current continuation: save `(ip, call_stack_depth, locals)` as
   a `ContinuationId` in a slab allocator on the VM.
2. Invokes the matched handler function with the perform args and the
   `ContinuationId`.

If no handler is found: runtime `EffectError::UnhandledEffect`.

## `Op::Resume`

Pops `(ContinuationId, value)` from the stack. Reinstates the saved continuation
state: restores `ip`, `call_stack_depth`, and `locals`. Pushes `value` as the
result of the original `perform` expression. Marks the `ContinuationId` as
consumed — a second `Resume` with the same ID is `EffectError::ResumedTwice`.

---

## Async scheduler rewrite

The M8 cooperative scheduler (`VecDeque<Task>` in `BytecodeVM`) is replaced.
Async concurrency is now implemented as a built-in `Async` effect handler (Task
6). The scheduler loop becomes a handler that intercepts `Async::Suspend`
performs and drives a `VecDeque` of pending continuations — exactly the same
semantics, now expressed as a handler rather than bespoke VM machinery.

`spawn` and `join` become handler operations, not special native functions.
Their semantics are unchanged; only the implementation moves into the effects
layer (registered by Task 6).

## Done when

- [ ] `BytecodeVM` has a `handler_stack: Vec<HandlerFrame>`
- [ ] `BytecodeVM` has a continuation slab keyed by `ContinuationId`
- [ ] `Op::PushHandler` pushes a `HandlerFrame` constructed from the operand stack
- [ ] `Op::PopHandler` pops the top `HandlerFrame`
- [ ] `Op::Perform` walks the handler stack and dispatches; missing handler emits `EffectError::UnhandledEffect` with span
- [ ] `Op::Perform` captures `(ip, call_stack_depth, locals)` into a fresh `ContinuationId`
- [ ] `Op::Resume` restores `(ip, call_stack_depth, locals)` and pushes the resume value
- [ ] Resuming a consumed `ContinuationId` emits `EffectError::ResumedTwice` with span
- [ ] The M8 cooperative scheduler (`VecDeque<Task>`) is removed from `BytecodeVM`
- [ ] All M1–M7 sync programs run unchanged
- [ ] M8 async programs continue to run once the built-in `Async` handler from Task 6 is registered
- [ ] `Executor` trait signature is unchanged (verify the existing replacement test still passes)
- [ ] All new runtime errors carry `Span` (Rule 5)
