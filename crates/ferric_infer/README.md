# ferric_infer

Hindley–Milner type inference with trait constraint solving. Stage 7 of the pipeline.

## Entry points

```rust
pub fn typecheck(
    ast: &ParseResult,
    resolve: &ResolveResult,
    interner: &Interner,
    registry: &TraitRegistry,
) -> TypeResult

// Backwards-compatible variant with an empty registry (no traits)
pub fn typecheck_no_traits(ast: &ParseResult, resolve: &ResolveResult, interner: &Interner) -> TypeResult
```

## Algorithm

Standard Algorithm J (HM inference) extended for traits:

1. Fresh type variables are allocated for every expression.
2. Constraints are generated by unification as the AST is walked.
3. Trait bounds are checked after unification — if a bound variable resolves to a concrete type, the registry is consulted for a matching `impl`.
4. Let-generalization produces `TypeScheme` for function definitions, enabling polymorphic use.
5. An occurs-check prevents infinite types.

`Ty::Unknown` is an escape hatch that unifies with everything without error. It is accepted in M2 code and intentionally removed in M3.

## Output

`TypeResult` contains:

| Field | Meaning |
|---|---|
| `node_types` | `NodeId → Ty` — the inferred type of every expression |
| `method_dispatch` | `NodeId → DefId` — method call sites resolved to concrete impl methods |
| `errors` | All type errors with spans |

## Type language

Primitives: `Int`, `Float`, `Bool`, `Str`, `Unit`, `ShellOutput`  
Compound: `Fn(Vec<Ty>, Ty)`, `Tuple(Vec<Ty>)`, `Array(Ty)`, `Struct(Symbol, Vec<Ty>)`, `Enum(Symbol, Vec<Ty>)`, `Option(Ty)`, `Result(Ty, Ty)`  
Async: `Async<T>`, `Handle<T>`, `Poll<T>`  
Inference: `Var(TyVar)` — resolved during unification
